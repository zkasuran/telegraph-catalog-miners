# Test cold-weather training without touching the reserved audit

This opt-in development path combines the original 128 legitimate training rows
with 64 supplemental cold-source training rows. Its 32 development-validation
rows use different station entities and month windows. Original validation and
audit rows never enter this path.

Only the controller-owned bounded public CPU workflow may load or train a model.
The local gate validates source cells, input hashes, literal rendering, grouped
splits and refusal paths without neural imports. All fitting happens on training
once in the remote job. The resulting integer shortcut coefficients and source
context are retained immutably with the selected package.

Training uses one rotating JSON, Celsius or bare representation per source
question, not repeated rows counted as independent material. The pinned upstream
trainer selects a completed checkpoint by JSON validation loss. Native JSON,
Celsius and bare-answer validation are recorded separately.
Those measurements are not reference-engine scores or an independent audit.

The development result is always marked DEVELOPMENT_ONLY. It cannot create
registration-ready.json, consume the original reserved audit or activate serving.
A fresh independent audit with the required source groups, actual parser and
reference-engine checks is still required before qualification.

Set the workflow's development_only input explicitly true for an authorized
experiment. It defaults false, leaving the original experiment and serving
paths in place. Never dispatch another event while an earlier POST is unresolved.

## Source and terms

The inputs are NWS CF6 source-flag-1 facts with retained source cells, annotations,
station IDs, dates, line numbers and capture hashes. They are not our copyrighted
government facts. Constructed preferences are AI-assisted, not human-reviewed
votes or natural miner responses. No protected pool capture enters development.

New additions use the family SAND terms. The unchanged primary trainer and kit
retain MIT. ModernBERT by Answer.AI and LightOn retains Apache-2.0 at revision
8949b909ec900327062f0ebf497f51aef5e6f0c8. Its primary card states: "We release the
ModernBERT model architectures, model weights, training codebase under the Apache
2.0 license." Full upstream grants remain in the family namespace and checkpoints.

This path is implemented source, not a measured model improvement or a canonical
win. No prior forecast issue-time or universal weather proof is provided.
