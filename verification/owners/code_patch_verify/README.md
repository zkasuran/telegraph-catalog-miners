# Check recorded CI claims without guessing a pass

This CODE_PATCH_VERIFY source pipeline preserves a requested repository, commit
and workflow attempt before comparing its passed claim with separately supplied
CI evidence. It is a useful off-chain reference and a guarded ModernBERT
experiment, not a registered judgment adapter.

## What is real

The reference has 24 passing source tests. Its failure controls cover swapped
attempts, wrong commits, missing evidence, native boolean refusal and complete
job pagination. The literal published renderer is checked from pinned primary
code without importing model tooling.

The 128/32/64 training, validation and audit originals are fictional diagnostics.
They retain disjoint identities and dates, but share a semantic generator.
Frozen train-derived length and answer-only frequency controls score 50%.
They are not human annotations or genuine measured CI outcomes.

The source-audit workflow runs two original process smokes on public CPU and
binds their actual exit codes to the GitHub run and commit. These are process
controls, not workflow conclusion labels and not model-quality evidence.

## Try the reference

Run `bash verification/owners/code_patch_verify/verify.sh` from the standalone
checkout. The gate uses the standard library only and never changes tracked
source bytes. It verifies frozen data, original grants, compilation, the literal
response contract and meaningful pass/fail controls. No model is loaded locally.

Use ci_reference.py on data/smoke.json for an honest claim. data/tampered.json
must exit nonzero. Missing evidence returns available=false with score=null.
Only completed success and failure are supported. Other conclusions stay unknown.

## The next model gate

The isolated node scorer cannot fetch CI status from an opaque URL. Neural mode
therefore refuses without caller-contract.json identifying reviewed caller
source and an independently constructed canonical request that demonstrates
trusted CI observations in the literal scoring prompt. A field inside the
candidate answer does not authenticate itself. No protected pool rows may be
used to establish this channel or as training/test material.

The bounded native recipe fits only training. Validation selects the frozen
state and the audit is measured afterward. A native pass still needs the full
node-compatible parser, actual pinned foundation engine, all claimed formats,
baseline margins and fresh node qualification. This pipeline does not emit
REGISTRATION_READY from expected values or expose a serving endpoint before
those checks. See SECURITY.md for the remaining limits.

AI assistance used agentrouter/gpt-6.1-sol. No human review is claimed. Reviewed
SAND terms cover our additions. Original ModernBERT Apache-2.0 and Telegraph
kit MIT grants remain attached to their portions and every neural export.

## Qualification source integration

The release gate includes literal ready-report and measured child-record source
controls. The child record is self-reported and does not establish model quality.
The source CPU mode runs the pinned node parser against labelled synthetic
training-record controls. Neural training still requires genuine trusted caller
evidence. Full reference-engine and independent factual qualification remain
unverified and no ready report is emitted from source test fixtures.

## Real reference baseline mode

The owned public CPU workflow can run runtime_baseline to measure the released
foundation/engine with an explicitly untrained control package. The result binds
actual run, commit, package hashes, full parser, runtime and repeated fixed-vector
bits. It is not a trained model, independent audit or registration candidate.
All neural assets and execution remain in the bounded public CPU job.
