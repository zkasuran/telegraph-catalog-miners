## Authored fixture source

All 224 zone groups are original constructed protocol messages on reserved `.test` names. No third-party dataset, evaluation row or captured miner answer enters the generator. Source text and preference construction are both AI-assisted original work. No human reviewed them. They are not measured DNS observations. Own SAND terms cover these additions.

The full constructed inventory is enumerated before splitting. All name/type siblings and reverse preferences share their whole zone group. The split report records normalized prompt, question-identity and canonical-JSON overlap. There is no source-held-out or time-held-out real-world dataset claim.

## Protocol references

[DNS1035] P. Mockapetris, RFC 1035, November 1987, section 4.1.1. https://www.rfc-editor.org/rfc/rfc1035.txt

Grant read: `Distribution of this memo is unlimited.` It covers the memo, not arbitrary third-party DNS TXT values. Section 4.1.1 assigns 0 to No error condition and defines nonzero response codes.

[NULLMX] J. Levine and M. Delany, RFC 7505, June 2015. https://www.rfc-editor.org/rfc/rfc7505.txt

This is a protocol reference for the null MX control, not imported training text. Lookup success and mail acceptance are different facts. The model input contains only newly authored messages.

[DOH] Google Public DNS JSON API. https://developers.google.com/speed/public-dns/docs/doh/json

The response's Status and Question structure shape the parser. Its HTTP success is not DNS NOERROR. No documentation example or third-party TXT value is copied into the fixture data. Two independently queried resolver outcomes are private development controls only. An API's availability is not asserted as a data training licence.
